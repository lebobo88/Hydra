## The flow (`covenant/plan.cov`)

```
flow Plan(goal: Text) -> Untrusted<Text> under PlanningFlow budget { usd: 3.00 } {
  let draft = ask PlanAuthor(goal)
  let review = judge draft with PlanReview by PlanCritic
  loop max 1 {
    if review.verdict == pass {
      let blessed = verify(draft, review)
      let rendered = ask PlanScribe(blessed)
      return rendered
    }
    draft = ask PlanAuthor(goal, feedback: review.notes, draft: draft)
    review = judge draft with PlanReview by PlanCritic
  }
  if review.verdict == pass {
    let blessed = verify(draft, review)
    let rendered = ask PlanScribe(blessed)
    return rendered
  }
  escalate human "plan-critic did not bless the plan within one revise round"
}
```

- Rubric `PlanReview v1` has four dimensions. `owners`, `acceptance` and `dependencies` are the checks in plan-critic's "Procedure" step 2. `approved` is the critic's decision from steps 3 and 4 and "Return format" (approved true or false). The verdict is `pass when approved == 1`, `revise otherwise`. The critic blocks on any fault and never approves "with reservations" (step 4), so the skill has no `fail` outcome.
- No head blesses its own work. The judge is `PlanCritic`, a different agent from `PlanAuthor`. `PlanScribe` receives only `verify(draft, review)`, which the runtime gives only when the verdict is `pass`.
- `loop max 1`: the body runs once, so plan-author gets at most one revise round and the critic judges at most twice. A second `revise` escalates without another author call. The skill names no cap. One revise round is the procedure the cost measurement uses. It is a default, not a measured limit. The scribe branch is written twice (inside the loop, and after it for the second review), because the language has no loop counter.
- `budget { usd: 3.00 }`. The longest path is two author calls, two critic calls and one scribe call. The measured runs below cost at most 0.56 USD per author call and 0.30 per critic call, and plan-scribe's one run (after 4) cost 0.1311. That path is about 1.85 USD, and 3.00 leaves headroom. It is a default from those runs, not a measured limit. No agent has a usd cap, so the checker's structural sum is 0 and W0302 cannot fire.
- **Three versions of the flow were measured** (all `cov run`, below). Version A (commit 9746080) had `loop max 2` around judge-then-revise and `pass when all == 1` over the three checks. In both of its runs, after a second `revise` it asked plan-author for a third draft that nothing judged (0.4314 and 0.1888 USD). Version B judged twice in sequence, the loop as above, and kept `all == 1`. In its run the critic blessed the first draft (`approved: true` in its notes) while scoring `acceptance` 0.95 and `dependencies` 0.9, and `all == 1` sent the draft back against the critic's own decision. Version C, the committed flow, keeps B's shape and makes the verdict the critic's `approved`.
- `PlanningFlow` has one invariant, `CAPPED` (`require budget`). The three imported covenants (`PlanAuthorImported` and the others) were empty as the import wrote them. Since the follow-up ("Follow-up: read-only made real") each holds `NO_WRITE` (`forbid fs.write("**")`) and `NO_SHELL` (`forbid shell("*")`).

### What differs between the two conditions

- **Tools.** Before, under `claude -p` with no permission flags, tool calls that needed approval did not run. The before run 2 critic said its listing of `squads/*/squad.yaml` "needed approval and didn't run", and steps took 1 to 6 turns. After, the runtime runs every agent with `permissionMode: "dontAsk"` and `settingSources: []` (`@covenant/providers` `claude.ts`), and `harness("*")` approves every tool. The agents read files: the after-1 critic cited `/home/user/hydra/squads`, the first author step made 3 to 12 model calls, and the after-4 scribe tried to import `hydra_core`. The SDK printed `CLAUDE_SDK_CAN_USE_TOOL_SHADOWED` once per agent call ("canUseTool will not be invoked for: Bash, Edit, Glob, Grep, NotebookEdit, Read, WebFetch, WebSearch, Write"). `permissionMode: plan` reaches only the generated Claude Code file (`extra claude`), not `cov run`. No file in either repo changed during the runs (`git status`). The after agents therefore have more tool access than the before ones. That is the largest behavioral difference, and it explains most of the first-step cost in after 1 and after 3. These runs used the sources at 50893a2. Since the follow-up the agents declare `fs.read("**")`, and in a `cov run` probe the agent was offered Glob, Grep and Read and no write or shell tool, plus this cloud session's own `mcp__claude-in-chrome__*` tools, which it did not call and which the runtime's guard would deny (see "Follow-up: read-only made real"); the runs were not repeated.

## Covenant issue from this pilot (draft; sessions cannot open issues)

1. **Input section wording.** The Claude emitter writes "`{name}` placeholders in the instructions above stand for these inputs:" whenever the agent has a prompt and an `input`, even when the prompt interpolates no input (`packages/emit/src/targets/claude.ts`, `section`, case `H.input`). That holds for all three agents here, so the sentence describes text that is not there. LANGUAGE.md §12 (l.1392) ties the section's explanation to placeholders. A wording for the no-interpolation case (for example "This agent's caller supplies these inputs:") would be accurate.
2. **NORMALIZATIONS.md** names no `## Input` section, because import never produces one. An agent that is imported and then given an `input` for a flow, which is the natural next step after a port, gets a difference outside both lists.
3. **`cov import` path rule.** It refuses a Claude agent file outside `.claude/agents/`, and a Claude Code plugin keeps agents at any path its manifest lists (here `plugins/hydra/agents/`). The workaround was to move the files first.
4. **The importer's `permissionMode` warning.** At 50893a2 this item said `uses harness("*")` gives the agents, under `cov run`, write and Bash access that the originals do not have under Claude Code, and that Covenant must resolve it. Both halves were wrong. Claude Code ignores `permissionMode` for plugin subagents (the RCA, citing Claude Code's sub-agents.md, and Hydra's own `tests/test_claude_native_configuration.py`), so the originals had every tool too. And it is spec behaviour, not a runtime defect: authority is `uses` plus covenant `forbid` (LANGUAGE.md §6, §7), and `harness("*")` is every tool (§6, C.21). Hydra's sources now declare the limit (follow-up below). The `PreToolUse` question is settled from the bundled runtime: the provider's hook runs the effect guard on every tool call except StructuredOutput, so a bare `allowedTools` name that skips `canUseTool` is still judged. What is left for Covenant is small and is no spec change (RCA fix B): the importer's warning (`key permissionMode has no Covenant construct; passed through in extra claude`) should also say that the key limits nothing under `cov run`, that Claude Code ignores it for plugin subagents, and that authority belongs in `uses` and `forbid`.
5. **`covenant.toml` header comment.** The comment that `cov import` writes says each model id the agent files named is listed, but the file lists none. The original agent files name only the aliases `opus` and `sonnet`.
